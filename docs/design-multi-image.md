# 多图交互设计（已确认意向，待实现）

状态：**规则已确认并已实现**（会话上限 48 / 单次拖入 24）  
最后更新：2026-07-27（与 progress 全量审查对齐）

## 1. 背景

当前主流程以**单张**为主。用户希望支持一次拖入/导入多张，在主界面框内浏览、追加与导出。

## 2. 已确认规则

| # | 规则 | 说明 |
|---|------|------|
| R1 | **拖入后自动全部处理** | 进入队列后无需点「开始」；后台自动抠完 |
| R2 | **单张 = 整框大图** | **仅当会话中始终只有 1 张且尚未因追加变为多张时**：占满主预览区 |
| R3 | **多张 = 网格 + 滚动** | ≥2 张：网格多列多行；放不下主框内**右侧纵向滚动** |
| R4 | **点图放大** | 网格中点击任一张 → 大图查看 |
| R5 | **大图左右切换** | 放大后 ←/→ 浏览同会话其它张 |
| R5b | **右键回网格** | 大图预览时**右键**返回网格；不设「返回网格」按钮 |
| R6 | **处理中禁止再拖入** | 队列未全部结束时再拖入/导入 → **提示不可**，不追加 |
| R7 | **空闲且已有结果时可追加** | 当前批**全部处理完**（展示态）后，再拖入一批 → **追加到列表末尾**并自动处理新图 |
| R8 | **单张结束后再拖 = 转网格** | 单张处理完后，再拖入 1 张或一批 → 旧结果 + 新图一并进入**网格逻辑**（不再整框单张） |
| R9 | **导出** | 网格中可**多选部分导出**，也可**全部导出** |
| R10 | **数量上限** | 见 §5 建议值（会话总张数 + 单次拖入张数） |

## 3. 界面状态机

```
空（0 张）
  └─ 🥝 拖入提示
  └─ 拖入 1 张 → 单张整框 + 自动处理
  └─ 拖入 ≥2 张 → 网格 + 自动处理整批

单张整框（会话仅 1 张）
  ├─ 处理中 → 禁止再拖入（提示）
  └─ 已完成展示
        ├─ 拖出 / 导出当前张
        └─ 再拖入 1 张或一批
              → 追加 → 会话 ≥2 → **切换为网格**
              → 仅对新图自动处理（旧图已完成保留）

网格（会话 ≥2 张）
  ├─ 处理中（任一张仍在队列）→ 禁止再拖入（提示）
  ├─ 全部完成后展示
  │     ├─ 再拖入一批 → 追加到末尾 + 自动处理新图
  │     │     （若超过上限：拒绝或截断并提示，见 §5）
  │     ├─ 点选若干 → 导出选中
  │     ├─ 导出全部
  │     └─ 点击一格 → 大图 + 左右切换
  └─ 滚动查看
```

### 3.1 「处理中」判定

以下任一成立即视为**忙**，拒绝新拖入：

- 仍有 item 状态为 `queued` / `running`
- （实现时）工作线程未空闲

提示文案建议：  
「当前批次仍在处理，请等待全部完成后再添加图片。」

### 3.2 单张 → 网格的触发（R8）

| 时刻 | 会话张数 | 展示 |
|------|----------|------|
| 只拖入 1 张并完成 | 1 | 整框大图 |
| 完成后又拖入 1 张 | 2 | **立刻改网格**（含上一张结果） |
| 完成后又拖入一批 | 1+N | **网格**，新图排队处理 |
| 一开始就拖入多张 | N≥2 | 始终网格 |

要点：整框单张**只服务「从空到只处理过一张、且未再追加」**；一旦追加，不再回到整框（除非清除会话回到 0/1——清除后若只留 1 张可再整框，可选实现）。

## 4. 处理策略

- 本机 rembg **session 复用**
- **串行队列**（推荐）：CPU 占用可控，进度好展示
- 单张失败不阻断：该格失败，其余继续
- 追加时：仅对新加入的 item 入队；已完成的不重跑

## 5. 数量上限——建议值（推荐采用）

分两层，避免「一次拖 500 张」和「会话无限涨」：

| 上限 | 建议值 | 理由 |
|------|--------|------|
| **会话最大展示/持有张数** `MAX_SESSION` | **48** | 约 4 列×12 行，滚动可接受；缩略图+路径内存可控；接近「两屏多一点」 |
| **单次拖入最大张数** `MAX_DROP` | **24** | 一次追加别太久；串行 CPU 下 24 张往往已是数分钟级 |
| 硬顶（不可配置时的天花板） | 64 | 防止设置被改炸；超过直接拒绝 |

### 5.1 为何不是 100 / 200？

- 本机 CPU 抠图：单张数秒～十余秒时，**50 张可能要十几分钟**，体验像「卡死」
- 每张保留原图路径 + 结果 PNG/缩略图，张数过多内存与临时盘上升
- 48/24 对商品图、证件照批处理够用；真要整文件夹上百张，应以后做「文件夹监视/导出到目录」而不是全塞进 UI

### 5.2 触顶行为（建议）

| 情况 | 行为 |
|------|------|
| 处理中再拖 | 全部拒绝 + 提示忙 |
| 空闲追加后总数 ≤48 | 全部追加到末尾 |
| 空闲追加后会超过 48 | **不追加超限部分**；提示「最多保存 48 张，还可添加 K 张」；能加的先加并处理 |
| 单次拖入 >24 | 只取前 24 张（或整拒——推荐**截取前 24 并提示**） |

设置里以后可把 48/24 做成可选项（进阶），默认用上表。

### 5.3 「批量处理多少张比较好」——直接回答

| 场景 | 建议 |
|------|------|
| **产品默认上限（会话）** | **48 张** |
| **一次拖入** | **≤24 张** 最舒服 |
| **日常建议用户** | 一批评 **10～20 张**，检查质量再下一批 |
| **不建议默认放开到** | 100+ 进 UI 网格 |

「批量处理」若指队列策略：一次会话内可连续处理最多 48 张（含追加），但**同屏等待感**最好按 24 一截。

## 6. 导出（R9）

| 能力 | 说明 |
|------|------|
| 网格多选 | Ctrl/Shift 或勾选框选中若干格 |
| **导出选中** | 仅导出选中且已成功的透明 PNG（失败的跳过并提示） |
| **反选** | 反转当前所有勾选，便于「先全选再去掉几张」的反向操作 |
| **导出全部** | 导出全部已成功项；可选目标文件夹 + 前缀 |
| 单张整框 | 与现在一致：导出当前 / 拖出 |
| 大图灯箱 | 导出/拖出**当前查看张**；选中状态可与网格同步（实现时定） |

## 7. 网格与大图 UI 细节

| 项 | 约定 |
|----|------|
| 列数 | 宽度自适应（约 3～4 列） |
| 格子 | 等待 / 进行中 / 完成（棋盘格缩略）/ 失败 |
| 大图 | 优先结果；未完成显示原图+状态 |
| 清空 | 「清除」清空会话，回到空状态 |

## 8. 与设置的关系
